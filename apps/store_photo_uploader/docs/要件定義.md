# 要件定義書 — 店舗写真アップロードフォーム

| 項目 | 内容 |
| --- | --- |
| システム名 | 店舗写真アップロードフォーム |
| 版 | 1.0 |
| 作成日 | 2026-09-03 |
| 位置づけ | 100周年特設ページ（`app.py`）とは独立した社内向け補助ツール |

---

## 1. 背景と目的

店舗ごとの写真を集めて一覧管理したいが、現状は次の手作業が発生している。

1. 各店舗から写真を受け取る（メール・チャット等）
2. 受け取った写真を Google Drive の所定の場所に手で保存する
3. 保存した写真の共有リンクを取得する
4. 管理用スプレッドシートの、その店舗の行にリンクを貼り付ける

本システムは **2〜4 を自動化** し、投稿者が「店舗名を選んで写真を送る」だけで
Drive への保存とスプレッドシートへの反映が完了する状態を目的とする。

### 達成したい状態

- 写真を受け取ってから台帳に反映されるまでの手作業をゼロにする
- 保存場所とファイル名の付け方を全店舗で統一する
- 店舗名の表記ゆれによる貼り付け先の間違いをなくす

---

## 2. スコープ

### 対象とするもの

- 写真と店舗名を受け付ける入力フォーム
- Google Drive への保存（店舗別フォルダ）
- 共有リンクの発行
- Google スプレッドシートへのリンク書き込み

### 対象としないもの

| 項目 | 理由 |
| --- | --- |
| インターネットへの公開 | 社内 LAN 内での利用に限定する |
| 投稿者のユーザー認証 | LAN 内からのアクセスに限られるため、初版では設けない（→ 8章） |
| 写真の編集・加工（リサイズ、補正等） | 投稿されたファイルをそのまま保存する |
| 投稿履歴の画面表示・検索 | Drive とスプレッドシートが台帳の役割を果たす |
| 投稿内容の承認フロー | 投稿は即時反映とする |
| 店舗マスタの管理機能 | 店舗一覧はスプレッドシートを正とし、そちらで管理する |

---

## 3. 利用者と利用シーン

| 区分 | 想定 | 使い方 |
| --- | --- | --- |
| 投稿者 | 各店舗の担当者 | 社内 LAN に接続したスマートフォン／PC のブラウザからフォームを開き、店舗名を選んで写真を送る |
| 管理者 | 本部の担当者 | サーバ機の起動・停止、設定変更、スプレッドシートと Drive の管理 |

### 想定利用量

| 指標 | 想定値 |
| --- | --- |
| 店舗数 | 数十店舗 |
| 同時利用者数 | 数名（多くても 10 名程度） |
| 1 回の投稿枚数 | 1〜10 枚 |
| 投稿頻度 | 常時ではなく、キャンペーン等の期間に集中する |

## 4. 機能要件

| ID | 機能 | 内容 | 優先度 |
| --- | --- | --- | --- |
| FR-01 | 店舗名の選択 | スプレッドシートに登録済みの店舗名から選択する | 必須 |
| FR-02 | 店舗名の手入力 | 一覧にない店舗名を手入力できる | 必須 |
| FR-03 | 写真の選択 | 複数枚まとめて選択できる。対応形式は JPG / PNG / WEBP / HEIC / HEIF | 必須 |
| FR-04 | 投稿前プレビュー | 送信前に選択した写真をサムネイル表示する | 任意 |
| FR-05 | 入力チェック | 店舗名未入力、写真未選択、枚数超過、サイズ超過を送信前に検出しエラー表示する | 必須 |
| FR-06 | 店舗別フォルダの作成 | 指定フォルダ配下に店舗名のサブフォルダを作る。同名が既にあれば再利用する | 必須 |
| FR-07 | Drive への保存 | 選択された写真を店舗別フォルダに保存する | 必須 |
| FR-08 | ファイル名の付与 | `YYYYMMDD-HHMMSS_連番_元のファイル名`（日本時間）で保存し、既存ファイルを上書きしない | 必須 |
| FR-09 | 共有リンクの発行 | 「リンクを知っている全員が閲覧可」を付与し、共有リンクを取得する | 必須 |
| FR-10 | 店舗名の照合 | スプレッドシートの店舗名列を走査し、投稿された店舗名と一致する行を特定する | 必須 |
| FR-11 | 表記ゆれの吸収 | 全角／半角、空白の有無、英字の大文字小文字の違いを無視して照合する | 必須 |
| FR-12 | リンクの書き込み | 一致した行の指定列のセルに共有リンクを書き込む | 必須 |
| FR-13 | 複数行一致時の扱い | 一致行が複数ある場合は全行に書き込み、対象行を画面に表示する | 必須 |
| FR-14 | 不一致時の扱い | 一致行がない場合も Drive への保存は完了させ、書き込みのみスキップして警告を表示する | 必須 |
| FR-15 | 結果表示 | 保存枚数、共有リンク、書き込んだセル、保存したファイル一覧を表示する | 必須 |
| FR-16 | 設定の外部化 | フォルダ ID、シート ID、シート名、対象列、開始行、上限値を設定で変更できる | 必須 |
| FR-17 | リンク対象の切替 | 共有リンクをフォルダ単位／ファイル単位のどちらにするか設定で選べる | 任意 |

### 4.1 補足: FR-08（ファイル名）の意図

同じ店舗が期間中に複数回投稿しても、過去の写真が消えないようにするための要件である。
タイムスタンプは投稿処理の開始時刻を全ファイルで共有し、同一投稿内は連番で区別する。

### 4.2 補足: FR-14（不一致時）の意図

「シートに書けなかったから写真も受け取らない」という挙動は、投稿者に再送を強いるうえ、
撮り直しが必要になる場合もある。**写真を確実に受け取ることを最優先** し、
台帳への反映は後から管理者が手当てできる、という考え方を採る。

## 5. 非機能要件

### 5.1 性能

| ID | 要件 |
| --- | --- |
| NFR-01 | 写真 1 枚（20MB 以下）の投稿が、社内 LAN と通常のインターネット回線において 30 秒以内に完了すること |
| NFR-02 | 店舗名の一覧は 5 分間キャッシュし、フォーム表示のたびにスプレッドシートを読まないこと |

### 5.2 可用性

| ID | 要件 |
| --- | --- |
| NFR-03 | サーバ機が起動しアプリが稼働している間のみ利用できる。24 時間稼働は要件としない |
| NFR-04 | サーバ機の再起動後、管理者が手動でアプリを起動できること（`start.bat`） |
| NFR-05 | Google API 側の障害時は、投稿者にエラー内容を画面表示すること |

### 5.3 セキュリティ

| ID | 要件 |
| --- | --- |
| NFR-06 | 社内 LAN 内からのみアクセスできること。インターネットに公開しない |
| NFR-07 | サービスアカウントの鍵をリポジトリに含めないこと（`.gitignore` で除外） |
| NFR-08 | サービスアカウントに与える権限は、対象の Drive フォルダとスプレッドシートに限ること |
| NFR-09 | 発行する共有リンクは「リンクを知っている全員が閲覧可」であり、リンクを知る第三者は写真を閲覧できる。この性質を許容できる写真のみを扱うこと |

### 5.4 保守性・運用性

| ID | 要件 |
| --- | --- |
| NFR-10 | 保存先フォルダ、シート、対象列の変更が、コード修正なしに設定ファイルで行えること |
| NFR-11 | 店舗名の照合ロジックと投稿フローが、Google API に接続せずテストできること |
| NFR-12 | セットアップ手順が文書化されていること |

### 5.5 動作環境

| 区分 | 要件 |
| --- | --- |
| サーバ機 | Windows PC 1 台、Python 3.11 以上、Google へのアウトバウンド HTTPS が通ること |
| 投稿者の端末 | サーバ機と同じ LAN に接続した PC・スマートフォンのモダンブラウザ |
| 外部サービス | Google Drive API、Google Sheets API |

## 6. 前提条件

| ID | 前提 |
| --- | --- |
| PRE-01 | Google Cloud プロジェクトで Drive API と Sheets API が有効化されていること |
| PRE-02 | サービスアカウントが作成され、鍵 JSON が取得済みであること |
| PRE-03 | 保存先 Drive フォルダと対象スプレッドシートが、サービスアカウントに編集者として共有されていること |
| PRE-04 | スプレッドシートに店舗名の列が存在し、店舗ごとに 1 行が用意されていること |
| PRE-05 | サーバ機と投稿者の端末が同じ LAN に接続していること |

---

## 7. 制約事項

| ID | 制約 | 影響 |
| --- | --- | --- |
| CON-01 | サーバ機の電源が入っていない間は利用できない | 投稿できる時間帯が限られる |
| CON-02 | サーバ機の IP アドレスが DHCP で変わると、投稿者のアクセス先 URL が変わる | 固定 IP または DHCP 予約の設定を推奨 |
| CON-03 | マイドライブに保存する場合、ファイル所有者がサービスアカウントになり、その保存容量を消費する | 共有ドライブの利用を推奨 |
| CON-04 | Google API には利用上限がある | 想定利用量では問題にならないが、大量一括投稿は避ける |
| CON-05 | 組織のポリシーによっては外部共有リンクの発行が禁止されている場合がある | その場合、保存は成功するが共有設定の付与に失敗し警告が出る |
| CON-06 | HTTP 通信であり暗号化されない | LAN 内限定という前提で許容する |

## 8. 今後の検討事項

初版のスコープ外だが、運用開始後に必要性が判明した場合に検討する。

| 項目 | 内容 |
| --- | --- |
| 簡易認証 | 合言葉の入力を必須にし、LAN 内の無関係な端末からの投稿を防ぐ |
| 投稿者名の記録 | 誰が投稿したかをスプレッドシートに併記する |
| 投稿日時の記録 | 最終投稿日時を専用列に書き込む |
| 自動起動 | サーバ機の起動時にアプリを自動で立ち上げる（タスクスケジューラ） |
| 写真の自動リサイズ | 保存容量と転送時間の削減 |
| HTTPS 化 | 社内 CA による証明書の発行 |

## 9. 受入基準

以下がすべて満たされたとき、本システムは要件を満たすものとする。

1. 投稿者の端末のブラウザからフォームが開き、店舗名の一覧がスプレッドシートの内容と一致している
2. 写真を投稿すると、Drive の指定フォルダ配下に店舗名のサブフォルダが作られ、その中に写真が保存される
3. 同じ店舗に 2 回投稿しても、1 回目の写真が残っている
4. 発行された共有リンクを、Drive にログインしていないブラウザで開いて写真が閲覧できる
5. スプレッドシートの、投稿した店舗名の行の指定セルに共有リンクが入っている
6. 店舗名を全角／半角や空白違いで入力しても、正しい行に書き込まれる
7. スプレッドシートに存在しない店舗名で投稿した場合、写真は保存され、画面に警告が表示される
8. 店舗名・写真が未入力のまま送信した場合、エラーが表示され送信されない
